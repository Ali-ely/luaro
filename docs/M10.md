## Build and verification commands

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build_m10.ps1 -MemoryChecks
powershell -NoProfile -ExecutionPolicy Bypass -File .\build_m10.ps1 -Interactive
```

The first runs normal tests and the Windows memory matrix. The second runs
normal tests and opens the application. Memory checks can run separately:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\verify_memory.ps1
```

For Linux with g++ and a configured Valgrind installation:

```sh
sh verify_linux.sh
```

The Linux script uses separate sanitizer and Valgrind executables, avoiding
attempting to run an ASan-instrumented binary under Valgrind. It stops on any
compiler/test/memory error. Shell scripts are kept with LF line endings.

## Ownership audit

World owns one player collection, event pointers in Queue, and command pointers
in Stack. Each role owns its dynamic array; DeleteCmd/ModifyCmd own their clones
until restoration transfers them to World. Pointer containers own their storage,
and World explicitly deletes their pointees. World and owning commands cannot
be shallow-copied.

Events keep IDs, never long-lived player pointers. Dead players remain in the
world, while administrative removal deletes them. Modifying undo replaces the
object with its saved clone; callers must look up its ID again. Kill history
owns value records and string copies, preserving names after deletion/renaming.

The production source audit found the intended two dynamic_cast expressions,
both in checked user-capability requests. Normal turns use virtual dispatch.
No banned standard stack/queue/list containers, global mutable production state,
smart pointers, lambdas, or external runtime libraries were introduced.
