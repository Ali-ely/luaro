## Events and ownership

Event.h and Event.cpp define abstract Event with source/target IDs and virtual
apply, describe, and destructor methods. Concrete classes are KillEvent,
HealEvent, VoteEvent, RevealEvent, and ShootEvent. Poison is a KillEvent flag
that requires a remaining poison potion.

World owns every event in its custom Queue of Event pointers. Enqueue transfers
ownership even on allocation failure. Processing applies and deletes each event;
World destruction deletes unprocessed events. Viewing never dequeues.

Events look up IDs when applied. Deleted sources/targets and dead targets are
ignored. Already committed actions from dead but still present sources resolve.
IDs are never reused. On exceptions, current/pending events are deleted and
execution guards reset. Applied effects are not rolled back; an interrupted
Night may retain protection until a successful Night cleanup. Failed turns
are not counted. Turn execution is not transactional or undoable.

## Ordering and decisions

Automatic Night actions queue through virtual dispatch in stable priority order:
Witch/Seer, wolves, then Villager/Hunter. Events resolve FIFO, so automatic healing
precedes wolf attacks. Manual events come first: an attack manually queued before
a heal can kill the target. The queue is never reordered.

- Witch automatically heals herself while healing remains. Manual healing can
  choose another living target. Poison is a manual choice. Each potion is
  consumed only when its valid event applies. Healing never resurrects.
- Seer inspects the lowest-ID uninspected living other player and prefers known
  wolves when voting. Knowledge changes when RevealEvent applies.
- Villager records neutral suspicion initially, then votes by highest stored
  suspicion with lowest-ID ties.
- Wolves share one lowest-ID living village victim per Night; repeated pack
  attacks cannot retarget after that victim dies. Werewolf records targets;
  AlphaWolf refreshes its living pack-member array.
- Witch/Hunter vote for the lowest eligible other ID; wolves vote against the
  village. Automatic decisions use role knowledge, not the administrator display.
- Hunter death queues a shot at the lowest-ID living other player. The death
  flag is set before the hook, preventing duplicate reactions. Shots append
  FIFO, including chains. Administrative removal does not trigger a shot.

Protection blocks attacks, poison, and shots, then clears at Night's end.
Vote elimination ignores protection.

## Votes and manual validation

The first valid ballot per source counts, so a manual vote overrides the later
automatic vote. AlphaWolf weight is two; others one. Tied highest totals or no
valid ballots cause no elimination. Hunter reactions after tallying resolve
before advancing. Ballots clear at the next Night's start.

Manual events require existing living participants; only Heal can target self.
Kill/Heal/Reveal/Poison are Night actions; Vote is Day. Heal/Poison require
Witch and Reveal requires Seer. Manual Kill is an administrator action allowing
any living source. A spent-potion request can queue but has no effect. Shoot is
created by the Hunter death hook.

Role checks are limited to manual validation. Normal action/event delivery uses
virtual methods with no casts. Low-level processEvents is a testing helper: it
does not advance phases, tally votes, or clear protection. The menu uses runTurn.
