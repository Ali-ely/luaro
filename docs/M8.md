# M8: complete console menu and input validation

Historical milestone walkthrough. M9 adds option 14 for statistics, a result in
the header, and early batch stopping at victory/draw. See [M9](M9.md).

## Run

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build_m8.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\build_m8.ps1 -Interactive
```

The first command tests and runs the unattended demonstration. The second tests
and opens the console with the initial eight-player village. A direct application
build runs interactively by default; `--demo` runs without reading user input.
Unknown command-line arguments print usage and return an error code.

## Commands

Existing menu numbers remain stable:

| Choice | Action |
| --- | --- |
| 0 | Quit |
| 1 | List all players, including dead players |
| 2 | View pending events without consuming them |
| 3 | Queue a manual Kill, Heal, Vote, Reveal, or Poison event |
| 4 | Run one turn (one Night or Day phase) |
| 5 | Run a batch of 1-1,000 turns |
| 6 | Create a selected role with defaults or custom values |
| 7 | Delete a player by ID |
| 8 | Duplicate a player with a new ID and independent role data |
| 9 | Modify name, alive, and protected flags |
| 10 | Undo the most recent successful management edit |
| 11 | Ask the selected player to inspect through Inspector |
| 12 | Ask the selected player to heal or poison through PotionUser |
| 13 | Show the selected player's complete details |

Choice 13 is an administrator display; it can reveal any player's role and
history. Choice 11 performs the Seer's gameplay action and queues a RevealEvent.
The header shows the next phase, completed turns, completed Night/Day rounds,
and undoable edits. Full winner detection and vote/kill statistics remain M9.

## Input behavior

All numeric prompts read one entire line into a string, parse a decimal int,
reject trailing non-whitespace text, and check the range for that prompt.
Letters, blank lines, fractions, multiple numbers, overflowing integers, and
out-of-range values print the allowed range and re-prompt. Leading/trailing
whitespace and an optional sign are accepted when the resulting value is valid.

IDs must be positive int values. Unknown IDs produce a message and return to
the menu. Role, event, potion, creation-mode, and flag prompts each use their
own valid ranges. A batch is capped at 1,000 turns per menu request so a very
large valid int cannot monopolize the console. World::runTurns still supports
its existing API range.

Names accept spaces and preserve the entered text. A whitespace-only name
re-prompts. For custom creation/modification, both flags must be 0 or 1. If dead
and protected are both selected, both flags are requested again while retaining
the entered name. World still validates values at its API boundary.

EOF at any prompt exits with `End of input. Goodbye.` An incomplete command
does not create a player, modify state, enqueue an event, or add undo history.
A complete final line works even without a final newline. Earlier completed
commands stay applied. Explicit choice 0 prints `Goodbye.` and exits.

Unknown players, incompatible capabilities, wrong phases, and unavailable
potions continue to use the established World validation. Rejected operations
return to the menu. Exceptions from individual actions print `Action failed:`
and allow another command; main catches exceptions that prevent the console
from continuing and exits with an error code.

## Implementation

Console.h and Console.cpp hold a small Console class that borrows World, input,
and output streams. All parsing helpers are private members. The application
passes std::cin/std::cout; tests supply string streams to exercise the same
menu and validation code without changing global streams.

The World and Console should share an output stream so action messages and
prompts appear together. Both borrowed streams and World must outlive Console.
The console owns no players, snapshots, events, or streams. It calls the existing
World operations; normal turns and the two checked capability casts remain in
their original locations. No extra casts were introduced.

Builds of main.cpp now link Console.cpp. Earlier model-only test commands do
not need it; the M4-M7 scripts have been updated to build the current application.

## Verification

The M8 tests run the real menu for all actions, mixed management/undo/event
scenarios, each role's default creation, custom values, single-player details,
invalid numbers and IDs, blank names, invalid flags, EOF at partial prompts,
final lines without a newline, bounded batches, empty worlds, and action
exception recovery. The maximum batch of 1,000 turns is exercised.

- GCC 13.1, C++17, `-Wall -Wextra -Wpedantic -Werror`: 92 M8 checks passed.
- Visual Studio AddressSanitizer: 92 checks passed without reported memory errors.
- Visual Studio debug heap: 93 checks passed, including no outstanding allocations.
- M6 and M7 regression suites: 157 and 74 checks passed.

World and role behavior were unchanged; earlier suites were not repeated.
