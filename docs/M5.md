# M5: create, delete, duplicate, modify

Historical milestone walkthrough. Management actions now record undo commands;
see [M6](M6.md) for restoration and snapshot ownership.

## Run and review

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build_m5.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\build_m5.ps1 -Interactive
```

The first command builds and runs tests and an unattended demonstration. The
second opens the menu after the tests. All builds use C++17 and
`-Wall -Wextra -Wpedantic -Werror`.

With the initial eight players, try this sequence:

1. Choose 6 (Create), role 1 (Villager), mode 1 (Defaults). The new ID is 9.
2. Choose 8 (Duplicate), ID 9. The copy gets ID 10.
3. Choose 9 (Modify), ID 10, name `Copy`, alive 0, protected 0.
4. Choose 1 (List). Player 9 remains alive with the default name; 10 is dead.
5. Choose 7 (Delete), ID 10. Player 9 remains, and 10's ID will never be reused.
6. Try modifying ID 999, a blank name, or alive 0 / protected 1. Each reports
   the error and returns to the menu without changing a player.

Custom creation (mode 2) asks for name, alive, and protected flags. Flags must
be 0 or 1. Whole-line integer input rejects letters, trailing text, and overflow.
EOF at any management prompt exits without applying a partially entered action.

## World API

| Operation | Behavior |
| --- | --- |
| `createPlayer(role)` | Role's default name, alive, unprotected, empty role data |
| `createPlayer(role, name)` | Custom name with default flags |
| `createPlayer(role, name, alive, protectedFlag)` | Custom shared attributes |
| `removePlayer(id)` | Delete and erase the owned object; false if unknown |
| `duplicatePlayer(id)` | Append a deep copy with a fresh ID; 0 if unknown |
| `modifyPlayer(id, name, alive, protectedFlag)` | Update shared attributes; false if unknown |

Invalid values throw `std::invalid_argument`; the menu catches exceptions and
prints a message. A name containing only spaces, tabs, or newlines is invalid.
A dead player cannot be protected. Names with spaces are supported. Unknown IDs
are checked before asking for edit values. Rejected actions do not consume IDs.

Only shared attributes are editable in M5. IDs and concrete roles cannot be
edited. Role histories remain intact and are filled by gameplay; custom creation
starts with empty histories. Administrative changes may revive a player, but
potions and histories are retained, so revival does not replenish a Witch.

## Copying and identity

Duplicate calls the source's virtual `clone()`, preserving its concrete type,
name, alive/protection flags, and independently owned role array. World then
assigns the next unique ID and appends the copy. Existing entries retain their
positions. `clone()` itself still copies the original ID for future undo snapshots.

Player declares World as a friend so World can change the duplicate's private
ID without exposing an unrestricted public ID setter. This is ordinary class
access control; no casts are used. Allocation/insertion failure deletes an
uninserted copy, and only successful insertion advances the ID counter.

Historical IDs within copied role data stay unchanged: inspection results and
past targets continue to refer to the players they originally described. They
are not rewritten to the new duplicate's ID. Duplicating a dead player creates a
dead copy, and duplicating a Witch preserves her remaining/spent potions.

## Editing and events

Validation precedes changes. Name assignment, which can allocate, occurs before
the flag updates. An invalid name or dead/protected combination therefore leaves
the entire previous state unchanged. The object, ID, role data, and vector position
remain the same after editing.

Administrative deletion or marking a Hunter dead does not invoke gameplay death
reactions. Events already queued keep their original IDs; deletion makes those
references harmless when resolved. Duplicating does not duplicate pending events
or ballots. Edits are allowed between turns even with queued events, and those
events see the edited state when applied. Protection still expires at Night's end.

All management actions are blocked while a turn or event resolution is running.
The menu reports unknown IDs and invalid values and continues. Management actions
do not advance the phase or turn counters.

create `build\m5_asan` and `build\m5_heap`, then run:

```bat
cl /nologo /std:c++17 /EHsc /W4 /WX /MD /Zi /fsanitize=address /I. /Fo:build\m5_asan\ /Fd:build\m5_asan\m5.pdb /Fe:build\m5_asan.exe Player.cpp Teams.cpp Roles.cpp World.cpp Event.cpp Command.cpp tests\m5_tests.cpp
build\m5_asan.exe
cl /nologo /std:c++17 /EHsc /W4 /WX /MDd /D_DEBUG /I. /Fo:build\m5_heap\ /Fe:build\m5_heap.exe Player.cpp Teams.cpp Roles.cpp World.cpp Event.cpp Command.cpp tests\m5_tests.cpp
build\m5_heap.exe
```

M5 stops here for review. M6 will add commands and multi-level undo, including
restoring deleted/modified players with the same state, ID, and list position.
